# ShopBonus asynchronous bridge — candidate 0.1.0

Magento Open Source / Adobe Commerce 2.4 self-hosted or PaaS only. Native installation, DI compilation, cron and real provider order/refund/uninstall acceptance are NOT RUN. This PHP module is not an Adobe Commerce SaaS/App Builder application and cannot be installed on SaaS.

Install the contents under `app/code/Shopbonus/AsyncBridge`, or install through a private Composer artifact repository. Enable `Shopbonus_AsyncBridge`, run the normal Magento setup/DI compilation/cache deployment procedure, and verify the declarative `shopbonus_async_outbox` table. Back up the native installation/database before module changes; follow the deployed Magento version's schema/whitelist procedures. No keys or merchant installation files are included.

In Stores > Configuration > Services > ShopBonus asynchronous bridge, select the exact **store view**. Enter the ShopBonus Magento webhook URL and signing secret, then enable delivery. Secret storage uses Magento's encrypted configuration backend. The Laravel connection must have the same store view ID/code, verified storefront domain and restricted native REST credentials. This is a server-to-server ID bridge, not a storefront publisher.

Enable the normal Magento default cron group. Order, invoice and credit-memo save-commit observers only update a local coalescing outbox; no external HTTP request occurs on checkout. Cron selects at most ten pending IDs, uses the configured Magento shared lock manager to prevent overlapping workers and sends signed ID-only notifications. Use a lock provider shared by every cron node. The existing bounded HTTPS/DNS-pinned delivery refuses redirects/private hosts. Queue failures are logged without secrets and do not fail checkout; configure ShopBonus native discovery/backfill to recover missed events and monitor native logs/outbox/cron.

Each pending event retains its ID/payload across retries. New order updates replace the event ID atomically. Delivery acknowledges only the version it actually sent, so it cannot mark a concurrent newer update delivered. Missing/invalid settings and unavailable ShopBonus stay pending with bounded backoff (30seconds up to1hour). A 200/202 confirms ingestion acknowledgement, not payment, wallet credit or code redemption. ShopBonus independently fetches native order/transactions/invoices/credit memos; authorization is not capture and credit memos alone are not cash settlement.

For shutdown: disable the **delivery configuration flag** first, wait for active cron workers to finish, reconcile pending IDs through native recovery, then disconnect/rotate the ShopBonus connection and remove per-store credentials. Remove the module only through the merchant's supported deployment process. Back up pending outbox records before any Magento module-disable/schema-cleanup step; do not drop pending evidence automatically. Delivered outbox rows can be purged under the merchant's retention policy after backend reconciliation. There are no storefront scripts to remove. Do not copy this PHP module into SaaS; use a separately authenticated out-of-process Adobe event application there.
