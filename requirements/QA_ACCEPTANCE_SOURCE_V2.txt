1. Evidence and no-skip protocol
Each check below receives one unique step ID (e.g. SB-21.03), its executable test name and a
machine-readable result. A green group means all checks plus relevant negative tests passed on the recorded
code SHA.
For EVERY check save: UTC timestamp; run/step ID; SHA; staging environment; actor/tenant; expected and
actual assertions; masked request/response and request_id; DB before/after; relevant cent-ledger/code IDs;
provider status; webhook/queue/audit records; browser screenshot/trace where visible; evidence file URI and
SHA-256.
Coverage gate: Export the Laravel route list, controllers/actions, Policies, Jobs, Events, Listeners, schedule,
webhooks and frontend calls; map all to approved tests. APIs not used by the current frontend are still
inventoried. For each route include success, input validation, anonymous authentication and role/cross-tenant
failures where applicable. Add tests beyond these 25 when needed.
Integrity gate: Fixtures run on isolated staging with real DB, Redis, queue workers, scheduler, Reverb and
provider TEST accounts. Unit tests or mocks supplement but cannot substitute a real provider-backed E2E.
Production systems, funds and user data are out of scope.
Evidence filename convention: SB-21.03_2026-10-26T091500Z_a1b2c3d_mollie-payment.json; source screenshots use the
same prefix. A scenario cannot be PASS if any mandatory evidence is missing.
