# Recommended CMS content acceptance contract v1

Technical definitions selected under owner delegation (“do whats recommended without intervention”, 2026-11-04), recorded in D-112. This is a new recommended contract, not a recovered copy of the unavailable original brief/PDF or175-check source. It does not change the separate original acceptance gate or grant release approval.

Five denominators must each have explicit, nonempty unique inventory IDs and the identical covered-ID set, exact deployment/source/frontend versions, source references and independent evidence review. Numeric percentages or known=true alone cannot prove discovery exhaustive. Missing frontend/source discovery remains unknown, never100%.

1. CMS-D01 saved editable fields: every inventoried source/field/locale/version/usage including backend and discovered frontend bindings. Empty/loading/fallback UI needs inventory; backend page JSON alone is insufficient.
2. CMS-D02 locale bindings: every required NL/EN/DE source binding and version, including human language/meaning review, stale/missing states, ALT and semantic invariants.
3. CMS-D03 media breakpoints: every inventoried media usage/version at desktop/tablet/mobile, original/recipe/artifact binding, ALT and integrity/restoration evidence.
4. CMS-D04 component contexts: every discovered route/locale/role/UI-state/viewport/component composition with real text, controls, overlays, crop/focus and browser proof; an isolated raster or API manifest is insufficient.
5. CMS-D05 staging executors: exactly CMS-T01–CMS-T23, each with current exact-build genuine execution, assertions, request/DB/ID/screenshot evidence and independent review. Backend regression fixtures cannot stand in for actual staging runs.

T01 discovery; T02 hardcoded-copy CI failure; T03 translated-but-unbound copy; T04 isolated hero edit/save/reload/audit/restore; T05 FAQ hierarchy/order/visibility/locale; T06 exit-editor navigation; T07 email/mailto consistency; T08 blog/case blocks/SEO/schema/sitemap/revisions; T09 genuine model EN/DE proposals/cost; T10 token/voucher/negation/payout guards; T11 commerce identity preservation across locales; T12 tenant/auth/CSRF isolation; T13 legal/consent/email/SEO/cache; T14 outage/budget/duplicate jobs; T15 changed-source stale evidence/impacted execution; T16 originals/JPG transforms/responsive WebP; T17 actual component previews at three sizes; T18 usage/global replacement/safe archive-delete; T19 exact cancelled/reset/restored image recovery; T20 upload/worker/storage/CSRF/size failures; T21 media/ALT audit/new locales; T22 genuine1000+ bulk/review backlog; T23 safe rich text/forms/video/download/consent-script persistence/rendering.

Each executor needs its reviewed version-controlled runner ID, unique approved JUnit key/case version, named responsible executor, reproducible instructions, positive assertions and independent result-bound review. T09 and T22 require genuine OpenAI confirmation in addition to the standard evidence kinds. All five denominators require coverage inventory evidence; D01–D04 also require exact-build frontend discovery. D05's ID set is fixed to all23 executors, not a self-selected subset. Complete structural proof still requires human review of truth, completeness and actual provider/browser behavior.
