# Versioned CMS media backend — B79

Backend source on `frank/moneybird-experiment-followup`, baseline `1fa850c` plus B79. Scope remains PARTIAL: no client editor, component preview renderer, usage registry or staging execution is established by this checkpoint.

All existing global CMS upload surfaces share one service. Each new upload stores exact uploaded bytes privately with SHA-256, plus a normalized compatibility image at the existing public URL. This preserves the submitted file, not a hypothetical source before browser cropping. Existing/legacy assets remain usable; recipes require a new original upload when no preserved original exists. No merchant/tenant media is implicitly shared into this platform-global library.

Immutable `cms-media-v1` recipes pin original checksum and encoded-pixel crop/rotation/flip/output-width settings separately for mobile/tablet/desktop. GD WebP derivatives are queued once per recipe/breakpoint; duplicate deliveries do not rewrite ready output. Inputs are bounded to 4 MiB, 6,000 pixels per axis and 12 million pixels. Outputs are capped at 2,048 pixels per axis and 8 MiB. Metadata is stripped from public files. Originals require current active Super Admin access and private no-store download. Public artifacts use opaque version-pinned URLs. Creating or restoring requires recent password confirmation and exact media revision; stale changes return409.

Restore verifies the preserved original and all three ready artifact checksums before switching the active manifest pointer. It reuses the exact stored artifact bytes rather than asking the renderer to reproduce them. Published content and old compatibility URLs are not rewritten by a pointer change. Renderer version/PHP/GD metadata is recorded. Cross-version recipes cannot be restored onto another asset. Revoked administrators cannot generate queued derivatives.

## Operations

Apply migration `2026_11_04_100000_create_cms_media_recipes`. Ensure private filesystem durability and GD JPEG/PNG/WebP support. Run a supervised worker such as `php artisan queue:work database --queue=cms-media --tries=1 --timeout=60`; `CMS_MEDIA_QUEUE_CONNECTION` defaults to database. Queue retry_after must exceed worker timeout. Include `cms-media` on the **actual database connection** in reliability monitoring: if default queue connection differs, set the existing `RELIABILITY_MONITORED_CONNECTIONS` JSON mapping for both actual connections (including `cms-translations`). Merely adding queue names to a Redis monitor does not observe database jobs.

Failed renders/dispatches expose failure codes and no public derivative URL. A killed worker may leave processing until its failed-job callback executes; inspect failed jobs and create a new recipe after correcting the underlying failure. Do not rewrite ready artifacts or bypass checksum checks. Back up both DB metadata and private originals/derivatives; the backup RPO and offsite recovery proof are separate deployment requirements. Existing API500/error audit and CSRF419 behavior is inherited, not demonstrated as real browser acceptance by the capture fixture.
