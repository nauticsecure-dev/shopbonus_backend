## Media lifecycle (B83b)

Migration `2026_11_04_140000_add_cms_media_archive_state` adds soft archive state. PATCH asset state requires current media revision, a reason, current Super Admin and recent password confirmation. It increments the media revision and audits the change. Libraries exclude archived assets by default; `include_archived=1` explicitly lists them. Originals, derivatives, public URLs and immutable published snapshots are retained. Existing draft references may remain at the same field path; new archived references are rejected inside the content transaction. Archived assets cannot receive new recipes; historical restoration remains available.

POST asset `/replace` takes at most50 explicit page/locale/revision/path selections and an active replacement asset with an optional ready same-asset recipe. All selected drafts lock before assets; any stale revision, changed source field, duplicate path or invalid pin rolls back the whole batch. Each selected locale increments once. Neither publication nor historical revisions are changed. This uses the saved-page usage inventory and does not claim all external/frontend usages are known. No physical deletion is provided.

Canonical AI dispatch now waits for the outermost content transaction to commit, including synchronous configurations. A rolled-back multi-draft edit cannot call the provider while its budget reservation/intent is rolled back. The regression checks both rollback/no-call and commit/one-call.

## Reusable text blocks (B83c)

Migration `2026_11_04_150000_create_cms_shared_blocks` adds a platform-global library plus immutable version rows. Each version records one allowed rich-text paragraph, heading, list or button, exact NL/EN/DE locale, author, monotonic version and content SHA256 (recursive object-key canonicalization; list order is preserved, including MySQL JSON normalization). Text blocks are capped at64KiB; nested references, images and arbitrary layouts/scripts are excluded. Media remains in the existing image pipeline. Library creation is unique-key protected; appending versions locks the current block revision. Old versions cannot be updated/deleted through the model. Preview provenance omits the mutable current block counter; exact version/number/hash/locale and editor/date remain recorded. Library/version reads are cursor-paginated and private/no-store.

Mount requires a current active Super Admin, recent password confirmation, exact draft revision and a version in that page's exact locale. Omit `index` to append; provide an existing root `body.content` index to replace it explicitly. Root nodes are materialized into ordinary allowed rich text, retaining public-client compatibility and stable published snapshots. `content.shared_blocks` maps at most20 root paths to immutable version IDs and optional overrides. Up to100 existing text/button-label paths may be overridden per usage; links, identities, structure, scripts and excess field lengths are rejected. No new renderer, global update, auto-publication or automatic shared-image replacement is introduced.

Ordinary create/save validates exact version integrity, locale and materialized body equality. Editing the pinned node without matching reviewed overrides fails422; dropping source pins silently fails409. Explicit revision-checked detach removes just one source pin while preserving that usage's text as ordinary page-owned content. Draft mount/detach are audited. Creating a new library version does not change any draft, publication or historical revision. Mount the new version explicitly and then use existing preview/publish procedures.

Bindings expose `shared_source` for each pinned field; preview includes `shared_usages` with exact version/hash/locale, overrides and resolved node. GET block `/usages?source=draft|revision` scans up to100 saved page rows per cursor. An empty page with `next` set is not proof of unused content. Exhaust both streams. Other models/client usages are explicitly unknown. Saved page versions contain the complete rendered node and source metadata, so public rendering never relies on a mutable library pointer.

AI improvement excludes pinned text from its input and output bindings. Translating a source with shared pins is rejected before queueing/provider execution; author/review a localized library version and mount it in the target locale, or explicitly detach the source before full-page translation. This prevents implicit NL/English borrowing into DE. Library translations themselves remain human-authored/reviewed; the canonical page AI flow does not silently rewrite reusable sources.
