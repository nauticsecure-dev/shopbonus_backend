# Verified support chat — #26 backend

Trello: https://trello.com/c/aWBrCkQK. Laravel backend only. No frontend/embed implementation. B17a evidence internals remain in [EVIDENCE.md](EVIDENCE.md); this document supersedes its original “not built” inventory for the components listed here.

## Configuration and deployment

1. Run migrations, including `2026_10_26_120000_create_support_chat` and `130000_create_support_knowledge_versions`. It adds support history/evidence/review tables only; no wallet/fee/policy activation.
2. Senior developer configures `OPENAI_API_KEY` locally and an account-supported `SUPPORT_AI_MODEL`; model/key are never returned by public APIs or placed in client code. `SUPPORT_AI_ENABLED=false` by default. Set true only after real model/privacy/budget verification.
3. Set global daily provider request cap (`SUPPORT_AI_DAILY_REQUEST_LIMIT=100`), per-user cap20, output token cap1000 (hard256–2000), total HTTP timeout20 (hard5–20), no redirects or HTTP retries. Every provider attempt consumes quota, including failures. A zero cap disables calls. Model capability and billed prices are not invented; the operations API reports measured token usage with cost unavailable.
4. A Super Admin drafts `support.ai` using the existing platform settings API: enabled, nullable model override, languages, daily_request_limit, timeout_seconds, max_retry0–1, restrictions. Test via `POST /admin/ai/settings/{version}/test`, submit for review, and a **different** admin publishes. Rollback creates a new draft which must be tested/reviewed/published. Environment enablement/caps remain upper bounds. No credentials in settings. Every settings/review/reply mutation requires recent password plus emailed OTP; admin MFA remains on in production.
5. Run the queue worker with timeout60/tries1; configure queue retry-after **greater than60seconds**. One database CAS claims a pending message. There are no automatic provider retries. A5-minute scheduler command `shopbonus:prune-support` recovers processing stalled for2minutes and pending requests older than1hour, then prunes expired history. Configure a real worker/scheduler monitor.
6. Install/deploy the included Laravel Reverb service (`laravel/reverb`1.12). Set app ID/key/secret, host/port/scheme and an explicit comma-separated `REVERB_ALLOWED_ORIGINS`; default origins are empty and server binds loopback. Set `BROADCAST_CONNECTION=reverb` only when configured. Use TLS/reverse proxy and supervised `php artisan reverb:start` in production. HTTP history/polling remains authoritative if broadcasting fails; failures are audited without making chat fail.

Source transport: [official OpenAI function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling). Responses uses a strict `verify_support_evidence` function with `tool_choice=required`, `parallel_tool_calls=false`, store=false. Laravel has already retrieved scoped live facts; the function requests **independent re-retrieval/verification**, not financial actions. The model selects opaque evidence IDs only; arbitrary prose, tools, amounts, dates, URLs, refusals, duplicate calls and malformed/incomplete output are rejected. No final free-form model text is displayed. Server EN/NL templates render source facts. Provider input excludes raw questions, account/workspace/source IDs, customer contact/payment data and voucher codes. Approved FAQ plain text is bounded4000characters and stays in Laravel; the provider receives only its version/scope metadata, not FAQ questions/content/contact text. All source text is untrusted data and never executable instructions. No model is hardcoded or live-verified here.

Reverb backend setup follows [Laravel13 broadcasting](https://laravel.com/framework/docs/13.x/broadcasting). Composer resolved Reverb's supported Guzzle/PSR7/Promises dependency ranges (Guzzle7, PSR7/Promises2); full application tests and composer audit verify compatibility. No NPM/frontend files are installed.

Workspace membership, state and individual permissions are rechecked before research, model egress and verification; nonmembers/nonowners404, members missing permissions403 within tools. Async denied research completes UNAVAILABLE with no answer/evidence disclosure; later revoked workspace history denies access. Consumer/workspace identity and permissions are never accepted from model arguments. Support impersonation cannot use these APIs or subscribe to private conversations. Current page is validated as a clean internal path but does not select tools or authorize actions. Server-generated links are only internal allowlisted account/workspace detail links; no model redirects/tracking parameters.

Idempotency is per user across conversations, with exact payload/scope hash; same key changed payload409. A conversation permits one active message under a row lock; the client waits or polls before sending another. Locale/workspace are pinned; continuations infer them when omitted. An authenticated user may submit an explicit different workspace only when starting a new authorized conversation. Responses contain only completed server-verified answers or clear non-answer statuses. Evidence timestamps are historical snapshots, not a promise balances never change.

Private channel: `private-shopbonus.support.conversation.{conversationId}`. Authenticate with the existing `/api/broadcasting/auth` route using the same Sanctum account. Only the current owner/authorized workspace member may subscribe, and support tokens are denied. Broadcast payload is exactly conversation_id/message_id/status; never questions, answers, model drafts or evidence. Event names: ChatResearchStarted, ChatVerificationStarted, ChatRetryStarted, ChatAnswerVerified, ChatAnswerUnavailable, ChatFeedbackSubmitted, ChatReviewRequired, ChatSupportReplyAvailable. Retrieve content through protected HTTP after an event; reconnect by refreshing conversation history/polling pending messages. Existing sockets cannot receive private content after revocation because none is broadcast.

## Research, policy and truth

Server bilingual intent planning is conservative: unsupported/ambiguous topics ask a specific clarification or open human review. References are validated and looked up inside ownership/scope. Missing references never trigger guessed financial answers. There are at most two research tool invocations; source rereads before/after the model are bounded integrity checks, not additional research/model rounds. A reward query starts with the consumer wallet and performs at most one **different** targeted owned order/reward lookup when a reference exists. No retry after401/403/404. If both reads fail the result is UNAVAILABLE, with bounded trace and human review; no provider call. If only a reward is verified, any wallet uncertainty is explicitly labelled partial. A provider error or incomplete selection never causes a retry loop.

Owned order linkage comes only from a consumer-owned issued/claimed voucher's source_order_id; **never email matching**. An owned EUR pending-credit public ID can also be checked: its status/amount are read from the existing wallet pending-credit record, payment/eligibility unknown unless separately proven, no release date. Paid orders and merchant voucher rewards remain separate from central spendable wallet credits. Available/pending/reserved/spent and points/EUR never convert implicitly. Quote uses the existing CheckoutService without creating wallet rows, payment or vouchers. Direct cost uses FeeCalculator; unavailable percentage caps remain unknown.

Campaign performance reuses BannerMeasurement (last30-day window) and counts only complete paid/partially-refunded attributed orders. **Tracked checkout/order starts are unavailable in the existing source, returned null**, never inferred as sales. Attribution does not establish causal uplift. Integration health uses actual connection status/last event and configured capability availability/verification; unsupported/untested capabilities remain unverified. Last event is not mislabelled a verified provider sync or successful redemption.

Immutable Laravel safeguards prohibit financial actions, refund guarantees, invented release dates, raw secrets, arbitrary claims/links and cross-scope evidence, independent of prompts/configurable rules. Configurable semantic restrictions use predefined rule codes and BLOCK/REWRITE/ESCALATE/REVIEW outcomes. REWRITE permits only existing server templates, never free model text. Refund/privacy/legal complaints always remain eligible for human review; a configurable BLOCK cannot suppress them. The settings test executes the100 static cases plus at most500 most recent human-approved correction cases. It records the exact policy checksum and regression corpus fingerprint; changed cases invalidate an unpublished test and require a new draft/test. Failed approved cases block publication without silently changing production. independent publication and canonical JSON hashes work on MySQL/SQLite. Critical rules cannot be disabled by a draft, prompt, vote or rollback.

Knowledge reuses published audience-scoped FAQ records. Existing FAQ create/update now preserve canonical-hashed immutable snapshots; a dedicated history/rollback API restores an approved published snapshot as a new revision under expected-revision locking, password+OTP and an audited reason. Legacy backfills identify unknown authors/times honestly; approved_at is null until an actual recorded admin publication. Existing versioned CMS page workflows are retained. To correct knowledge, a human publishes the reviewed source through CMS/FAQ management, then resolves the review with its published reference or documents an audited code/policy correction. CONFIRMED_ERROR adds an approved regression case; thumbs-up alone proves nothing and unreviewed votes never change behavior. Human regression questions are encrypted and retained with their conversation; static100 cases remain in `resources/support/regressions.php`. The production model/policy does not auto-train on feedback.

## Retention and operation

Conversation expiry is pinned at creation, default30days, configurable1–90. Question/research/evidence/result/feedback comments/human replies/regression questions are encrypted at rest. Only current owners and scoped Super Admin review routes can decrypt them. Explicit deletion and scheduler expiry remove the private history and dependent records; audit keeps sanitized references, not questions or evidence. Existing account privacy requests retain their current manual workflow; this work does not claim automatic account erasure. Support transcripts are removed through the owned deletion endpoint or scheduled expiry. Retain policy versions/test reports as non-customer configuration evidence.

Global and per-user daily quotas serialize through DB row locks. Three provider failures open a5-minute circuit; model refusals/invalid output fail closed. Queued duplicate execution is CAS-guarded, failed-job recovery cannot overwrite a completed answer. Async processing returns UNAVAILABLE with null answer when disabled/unconfigured, rate-limited, stale, conflicting or unavailable. Optional escalation creates an actual review; no payment, refund, voucher issuance or outbound contact is performed. Provider billing is not available; use the OpenAI project budget and measured usage in addition to local request/token caps.
